# starikov.io v1.1 — production polish wave

## Context

v1.0.0 shipped 2026-07-19 and the architecture held, but Illya's verdict is "rough around the edges — make it really good, production-ready, up to spec." Three audits confirm it: a spec-compliance audit (17 gaps against the site's own design spec), a code-level sweep (37 user-visible rough edges), and a live browser pass that reproduced the worst ones. This wave closes every user-visible defect and spec violation; spec-sanctioned v1.1 *features* (essay stubs, per-page OG endpoint, g-chords, /notes) stay deferred as the spec intends.

Worst confirmed-live defects:
- **Theme popover** (the signature control) renders half off the left viewport edge and below the fold on every desktop page.
- **/projects and /bin unreachable** from the sidebar (index links only render in branches that never fire).
- Home page: ~60% duplicate rows across its three sections; hero is a 7-line wall on desktop and fills the whole first mobile viewport; "press ⌘K" shown on touch.
- **2.9MB PNG** + unoptimized academia media; CLS violations on 5 routes; /writing at 119KB raw vs 40KB budget.
- No print styles (dark themes print near-blank); browser-default MDX tables; no h4-h6/blockquote/hr prose styles.
- ⌘K "Jump to" reaches almost nothing (PAGE_ITEMS has one entry).
- A dozen honesty-debt items where the site contradicts its own doctrine (opacity on text on /colophon, hardcoded "live" stats, missing freshness disclosures).

Repo: `/Users/starikov/Library/Mobile Documents/com~apple~CloudDocs/Documents/development/starikov.io` (quote — spaces). Ship progressively on main (established consent); CI gates (BUILD_STRICT, vitest, validate-dist) keep failed builds from deploying.

## Execution shape

8 tasks in order (foundations before consumers; ordering constraints from the design pass are baked into the sequence). Each task: implement → `BUILD_STRICT=1 npm run build` + `npx vitest run` + `npx astro check` (real runs, never stale IDE diagnostics) → commit → push → confirm deploy green.

### Task 1 — Broken interactions

1. **Theme popover** — `src/components/ThemeControl.astro` + `src/scripts/theme-control.ts`. JS-anchored `position:fixed` (escapes the sidebar's overflow clip; no ancestor creates a fixed containing block — verified). `open(anchor)` measures via `visibility:hidden`, prefers opening **upward** (`bottom = innerHeight − rect.top + 8`), clamps `left` to viewport with 8px gutters; `max-width: calc(100vw−16px)`, `max-height: calc(100dvh−16px)`, internal scroll. Reposition on `window.resize` + capture-phase document `scroll` (catches sidebar scroll); close on `astro:before-swap`. `aria-haspopup="dialog"` on the trigger; non-modal focus pattern: keep Esc/outside-click/arrow-roving, add close-on-tab-out via `focusout` (ignore null relatedTarget), return focus to the actual opener (sidebar pill **or** SystemCard row — the only two triggers; there is none in the mobile topbar, verified). Keep select-doesn't-close (deliberate compare-themes behavior). Add the missing `:hover`/`:focus-visible` states on family/mode rows.
2. **Sidebar reachability** — `src/lib/nav.ts` + `src/components/Sidebar.astro`: always render section index links ("All projects →", "All tools →") instead of only in empty/overflow branches. nav.ts unit tests for the three states (backlog #12).
3. **Copy button escapes its scroller** — `src/pages/bin/[tool].astro`: move the absolutely-positioned copy button out of the `overflow-x` `.clone` container into a non-scrolling wrapper.
4. **Mobile nav sheet vs resize** — `src/scripts/shell.ts`: close the sheet when crossing ≥1024px.
5. **Anchor offsets** — one shared `scroll-margin-top` (clears the sticky topbar) across bin/[tool], projects/[...slug], colophon, academia + align shell.ts scrollspy `rootMargin`.
